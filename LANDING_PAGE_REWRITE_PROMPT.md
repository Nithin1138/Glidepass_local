# LANpad Landing Page Rewrite Prompt

Use this prompt to rewrite or upgrade the LANpad landing page so it accurately reflects the full product experience across the desktop app, website, resource sharing system, creator/contributor workflow, and clipboard features.

---

## Objective

Redesign the landing page to clearly communicate that LANpad is a local-first productivity platform for students, developers, creators, and power users. The page should explain that LANpad combines:

- a local desktop app for instant phone-to-computer transfer
- clipboard and input workflows for fast text delivery
- a resource-sharing ecosystem for code snippets, notes, links, templates, and study materials
- a creator/contributor system for publishing and sharing resources
- a clipboard room feature for temporary sharing across devices without friction

The landing page should feel modern, trustworthy, and practical, not overly technical or vague.

---

## Product Context to Reflect

Use the full current product scope from the repo:

### 1. Desktop App
- Local-first Mac/Windows application
- Runs a local server and pairs devices using QR-based local connection
- Supports phone-to-computer transfer and input workflows
- Focuses on privacy and local-network operation

### 2. Clipboard & Input Workflows
- Quick transfer of text and snippets
- Keyboard-style typing simulation for paste-restricted or locked environments
- Flash / Paste, Type, Inject, and Live Sync workflows
- Useful for developers, students, and anyone working across devices

### 3. Resource Sharing Ecosystem
- Users can browse shared resources from the website experience
- Resources include code snippets, notes, links, templates, and reusable content
- Resource discovery is a core product value, not just a side feature

### 4. Creator / Contributor / Publish Flow
- Creators can publish resources
- Contributors can join hubs and contribute items
- There is a structured publishing ecosystem around hubs, categories, topics, and discovery
- The website acts as a distribution and collaboration layer

### 5. Clipboard Rooms
- Temporary clipboard rooms can be created for sharing text, code, and files
- Works without requiring a full account for basic use
- Useful for quick collaboration and sharing across devices

### 6. Privacy and Local-First Positioning
- Core app experience is local-first and private
- The product is designed to avoid depending on cloud transfer for everyday workflows
- Trust, privacy, and low-friction setup should be emphasized

---

## Target Audience

The landing page should speak to these groups:

- students using laptops and phones for study, labs, assignments, code reference, and revision
- developers and engineers who want a fast way to move code, snippets, and text between devices
- creators and contributors publishing useful resources to a community
- users who want a simple clipboard and sharing workflow without signing up for a giant SaaS product

## Landing Page Sections to Include

Create a landing page with the following sections in this order:

### 1. Hero Section
Must include:
- a strong primary headline
- a short subheadline explaining the value clearly
- primary CTA: Download / Install LANpad
- secondary CTA: Explore Resources or Try Clipboard
- a short proof bar or trust line such as “Local-first”, “No cloud lock-in”, “Fast phone-to-computer sharing”

Suggested content direction:
- headline: communicate that LANpad helps users move text, code, and resources instantly between devices
- subheadline: explain that it is privacy-friendly, local-first, and built for real productivity flows

### 2. Problem / Why It Exists
Explain the pain points the product solves:
- switching between phone and computer is annoying
- clipboard sharing is fragmented
- cloud-based tools add friction and privacy concerns
- students and developers need fast access to useful snippets and reference material
- sharing resources should feel simple and immediate

### 3. Product Overview / Core Experience
Show that LANpad is more than a clipboard tool. It should include three product layers:
- Desktop app for local transfer and input
- Resource sharing ecosystem for snippets and useful links
- Clipboard rooms for temporary sharing across devices

### 4. Key Features Section
Present the key capabilities in a clear, visual grid:
- Instant phone-to-computer text transfer
- Typing and injection modes for paste-restricted environments
- Resource discovery and sharing
- Publish resources as a creator or contributor
- Temporary clipboard rooms for quick collaboration
- Local-first privacy and secure local pairing

### 5. How It Works Section
Show a simple 3-step flow:
1. Install and launch the desktop app
2. Connect your phone through the local QR flow
3. Start sharing text, snippets, resources, or clipboard rooms instantly

Keep it simple and visual.

### 6. Use Cases Section
Highlight legitimate, practical scenarios, for example:
- coding and lab work
- revision and study workflows
- team collaboration and quick sharing
- creator publishing and resource discovery
- clipboard-based transfer across devices

Avoid anything that sounds like misuse or bypassing security. Keep it fully legitimate and product-focused.

### 7. Resource Sharing / Creator Ecosystem Section
This should be a major section because it is a unique product layer.

Include:
- discover public resources
- browse hubs and categories
- publish useful snippets and links
- contribute to communities and topic-based hubs
- send a resource directly into the local app experience

This section should make the website feel like a real product layer, not just a marketing site.

### 8. Clipboard Rooms / Quick Share Section
Explain the temporary clipboard-room capability in plain language:
- share code, notes, or files quickly
- create a room and share a link/code
- no account friction for basic use
- useful for short bursts of collaboration

### 9. Install / Get Started Section
Show install options clearly:
- macOS download
- Windows download
- terminal install flow for macOS
- PowerShell script for Windows
- links to setup docs and support

This should feel straightforward and official.

### 10. Privacy / Security / Trust Section
Show the trust story:
- local-first architecture
- private pairing over local network
- no unnecessary cloud dependency for core flows
- clear legal links and policies

### 11. Final CTA Section
End with a strong closing CTA:
- Install LANpad
- Explore resources
- Try clipboard rooms

### 12. Footer
Include links to:
- Privacy Policy
- Terms of Service
- Cookies Policy
- Support
- Resources
- Contributors / Creator flow if relevant
